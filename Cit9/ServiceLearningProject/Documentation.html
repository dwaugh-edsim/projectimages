Student Workflow

The system guides students through a structured 5-phase process:

  1. Choose & Commit: Select mission and establish personal rationale
  2. Research Foundation: Answer 4 guided questions with sources
  3. Plan Roles: Assign team responsibilities (Technical, Logistics, Communications)
  4. 14-Day Action: Execute phase-specific activities with daily logging
  5. Impact Report: Compile findings into collective report

Students progress through the Menu.html → Briefing.html → Dossier.html sequence, with all data synchronized to the cloud backend.

Deployment Instructions

Frontend Files

Place all HTML files in your web server directory accessible to students:

  • Ensure Menu.html is the main entry point
  • Verify all internal links point to the correct consolidated files
  • Test cross-browser compatibility (Chrome, Firefox, Safari, Edge)

Backend Configuration

Deploy the Google Apps Script:

  1. Open Google Sheets and navigate to Extensions → Apps Script
  2. Replace the default script with the content from code.gs
  3. Deploy as Web App with access "Anyone" or "Anyone with Google account"
  4. Update the WEBHOOK_URL in all HTML files with the deployment URL

Testing

Validate the complete workflow:

  • Login functionality with various student PINs
  • Data synchronization between devices
  • Form submission and download features
  • Progress tracking in the dashboard

Conclusion

The consolidated Service Learning Project structure streamlines operations while maintaining all educational functionality. With 4 primary files managing the complete workflow, educators can focus on facilitating student learning rather than managing technical complexity.

The system supports scalable implementation across multiple classes while providing granular progress monitoring. All original functionality is preserved in a more maintainable and efficient format.
